# REA evidence checklist

These notes capture static observations from the installed Klimper 2.4 ARM64 binary. They support evidence-led investigation; they do not establish 1:1 runtime parity.

- [Project model](PROJECT-MODEL.md): serialized project and recursive section/clip shapes recovered. Recursive section-query routines `FUN_10002ad90` and `FUN_10002b004` establish nested note origins and sequential chord placement; they are project-model queries, not Tonal scorers. Scale steps are cumulative semitone deltas (C Major `[2,2,1,2,2,2,1]` expands to `[0,2,4,5,7,9,11]` from C), while `chord.intervals` remains a separate unresolved representation. The internal unit is 10,368 ticks per whole note and 2,592 per quarter-note beat. Pitch meaning, instrument routing, and several edit transforms remain open.
- [Instrument resolution](INSTRUMENTS-SPEC.md): static evidence closes parsed Track/ChordTrack instrument strings through scheduler event `+0x20`, ProjectPlayer note-on, and Soundfonts exact source-map lookup. The writer copies fields directly; the separate `instrument_of` closure's creator/flag initialization remains unknown. Mute/solo gates event volume before dispatch. Selector command semantics, key-to-file/preset mapping, and per-Track MIDI channels remain open. See [queue producer validation](QUEUE-PRODUCER-VALIDATION.md), [instrument queue validation](INSTRUMENT-QUEUE-VALIDATION.md), and [instrument callback join validation](INSTRUMENT-JOIN-VALIDATION.md).
- [Section transforms](SECTION-TRANSFORMS.md): serialization, path traversal, a nested-length max update, and one section-append path are recovered. Move/resize/wrap/duplicate operations and descendant offset rules remain unknown.
- [Editing specification](EDITING-SPEC.md): selected-note transpose, time-move deltas, selected-note deletion with undo restoration, tag-3 in-process copy/paste, and a generic length-edit command with a 649-tick minimum are recovered. The Delete menu-to-handler mapping, item-kind mapping, drag-delta conversion, and other edit operations remain unknown.
- [Harmony](HARMONY.md): Flow, Contrast, Match Notes, and both Tonal callback branches have recovered arithmetic and derived-vector coverage. Palette base/extension candidate generation and voicing arithmetic are partly traced; final collection flattening/display order and score-to-visual mapping remain unknown. Preview Octave/Strumming controls are statically linked to the palette producer's register/spacing state.
- [Playback](PLAYBACK.md): integer-tick scheduler, event windows, loop-boundary cleanup, and chord-preview spacing/velocity paths are recovered to bounded static code paths. PreviewSettings Octave/Strumming state is directly aliased to the palette producer's register/spacing state. Full-song export, MIDI input, Track-to-channel mapping, producer gain/root-threshold settings, output callback sound behavior, and loop-field mapping remain partial or unknown. Clone smoke evidence describes the clone only.
- [MIDI clip export](MIDI-EXPORT.md): one selected-note clip-drag writer has a scoped SMF specification; this does not specify full-song export or every selection path.
- [Palette reconstruction](PALETTE-SPEC.md): evidence-backed base and extension candidate production, nested record ordering, semitone-step expansion, observed C Major default, and derived voicing vectors. The ModeSelector source/base path receives `KlimperApplication.this+0x80` as `Project&`, stored at `ChordPaletteContent.this+0x170`; separately, producer callback `FUN_1000cd82c` reads Scale through its captured `Observable<ChordSymbolisation>&` at `+0x170`. Do not conflate these owner-relative offsets. The selector-current-to-producer trigger and final SwiftUI flattening/order/display remain unresolved.
- [ModeSelector binding](MODE-SELECTOR-VALIDATION.md): distinct source-fed baseline and current Scale bindings, initial follow state, and left/right fifth actions. caller-supplied-source-to-baseline is established; current-to-generator invocation remains open.
- [Project document lifecycle](DOCUMENT-SPEC.md): bounded `.klp` open/save flow, JSON contract, defaults, loop-bound conversion, and typed-reader failure boundaries. An “Import Klimper Project” artifact string is observed, but its UI association and action target are unestablished; user-facing error recovery remains untraced.
- [Reconstruction plan](RECONSTRUCTION-PLAN.md): reconciled subsystem specifications, priority evidence gates, source-boundary map, and implementation milestones before prototype work resumes.
- [REA tooling status](TOOLING-STATUS.md): current read-only REA availability and local provider prerequisites.

All completed claims should cite their REA Evidence IDs, name their evidence type, and state coverage limits. A feature name or persisted field alone is not proof of its user-visible behavior. Keep unresolved claims marked unknown until new static or controlled runtime evidence supports them. No prototype behavior, build, test, or QA result establishes Klimper behavior.
